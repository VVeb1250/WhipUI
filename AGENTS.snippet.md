## Whip UX/UI Combo

Use `whip-design` for unresolved product/UX decisions, flows, IA, taste exploration
and design-only work. Use `whip-ui` for actual UI construction, reproduction,
extension, redesign, repair and rendered verification. Either entry can continue
through an already authorized task without a second invocation.

The shared core selects bounded source expertise and reconciles its defaults.
Read known context before asking; ask only material decisions and show real
references/variants when useful. Preserve approved intent and existing contracts.
Do not activate every source or run every pipeline. User decisions, proposals,
delegated assumptions and observed evidence remain distinct.
