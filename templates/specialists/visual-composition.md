## Choose a shape that serves the content

Start from what people need to read, compare or do, not a palette label.
These adapted page shapes are candidates, not defaults or a complete catalogue.
For application screens, keep the task flow and navigation established by
WhipDesign; a marketing-page shape must not replace an interactive workspace.

| Content or task | Candidate composition | Watch for |
| --- | --- | --- |
| Compare a collection | Catalogue: repeated inventory with consistent comparison fields | Decorative card variation that makes comparison harder |
| Understand a sustained argument | Long document: continuous reading with meaningful sections | Hiding the next action in a wall of copy |
| Learn how a product works | Workbench: representative screens paired with task explanations | A screenshot tour mistaken for a usable application |
| Find a destination quickly | Index-first: clear grouped links and orientation | Ambiguous labels or excessive navigation levels |
| Understand relationships | Map/diagram: spatial connections with a readable alternative | Inaccessible spatial-only navigation or a mobile dead end |
| Try a developer component | Component playground: interactive example with code | Controls without keyboard support or recoverable states |
| Judge visual work or goods | Photographic/portfolio: purposeful imagery with useful metadata | Generic imagery, unreadable overlays or slow oversized assets |

If none fits, compose around the actual content and task rather than forcing a
catalogue entry. For example, a reading tracker may prioritize continuing a book
and recording progress, not a giant promotional hero or an inventory-only grid.
Use representative titles, quantities and awkward lengths to test the choice.

## Make coherent visual decisions

Consider heading location, body layout, section boundaries, action treatment,
imagery and motion together. A narrow reading measure with occasional wide
illustrations supports a different rhythm from a dense comparison surface.
Whitespace, rules and background changes can separate sections; choose according
to grouping needs. Make actionable controls recognizable, not merely decorative
typography. Use imagery to explain or establish character, not to fill every gap.
Motion should explain change, respect reduced motion and never delay a task.

Do not randomize these axes or enforce differences between consecutive pages.
Preserve approved typography, components and navigation across the same product.
Novelty is useful only when it improves the brief's identity or communication.
Centered headings, cards, serif type and gradients are choices, not automatic
failures. Diagnose repetition against the actual content, not a blacklist.

## Resolve uncertainty with visible evidence

Choose a defensible direction autonomously when the brief permits it. Ask only
when missing information changes the task or a consequential constraint.
Compare structurally different small slices when uncertainty warrants it,
using the same content and primary task. Recoloring one layout is not a
composition comparison. Do not invent testimonials, metrics or customer logos;
label demo content and use assets with appropriate permission.

Render and inspect the chosen slice at relevant viewport sizes, including
keyboard focus and meaningful interaction states. Evaluate hierarchy, reading
rhythm, density, action clarity and task completion separately from visual
character. Imagining a screenshot or assigning a self-score is not verification.
If browser access is absent, mark visual/interaction QA untested.

Keep the selected direction, rationale and evidence in the existing Design
Fingerprint. No Hallmark log, separate design store, CSS stamp or extra MCP is
required. Return to the owning WhipDesign workflow for refinement.
