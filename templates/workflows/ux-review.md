# UX review: task evidence first

Scope the review to the user's actual question. Review requests are read-only.
A request to fix issues permits scoped changes, not a wholesale redesign.

Read [UX foundations](../specialists/ux-foundations.md) for heuristic lenses and
finding priorities. These bundled Sumi adaptations require no extra installation.

1. Choose the primary task from the brief/DNA. State starting conditions and
   an observable completion condition. Frame it as a user's goal rather than
   prescribing which controls to click.
2. Inspect the information hierarchy, labels and decision points. Distinguish
   unnecessary effort from necessary confirmation, consent or error prevention.
3. Exercise the task in the running UI when available. Include the relevant
   empty/error/recovery paths, keyboard use and narrow-screen behavior.
   Use test data and safe local actions. Do not submit real purchases, messages
   or destructive operations without user authorization.
4. Record each consequential finding: task, observed behavior, evidence path,
   impact, likely cause, smallest useful correction, and uncertainty.
5. Separate outcomes:
   - functional/browser observation: what the tool actually completed;
   - heuristic assessment: the agent's interpretation of likely difficulty;
   - human usability evidence: only real participant observations supplied or
     collected with permission.
6. If fixes are requested, prioritize task blockers and comprehension/recovery
   issues, then re-run the same task. Preserve visual identity on UX-only work.

Report task outcomes as observed / blocked / not tested, with evidence. Use
completion time, errors and success rate only when actually measured with stated
conditions; an automated browser's timing is not human time-on-task.
Do not average critical task failures away with high visual scores.
Source-only inspection is useful but cannot establish actual user comprehension.

For validation with people, propose realistic non-leading tasks and consented
sessions. Mark that study as proposed until performed. Automated accessibility
checks and agent walkthroughs cannot replace it.
