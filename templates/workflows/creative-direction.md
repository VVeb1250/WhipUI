# Visual exploration

This replaces the old Creative Direction Gate. Read only when new visual
direction is needed. Reference-led implementation and small UI edits do not
require novelty, three candidates, a signature move or a logo-swap test.

Start with WhipDesign's primary user task and experience structure. Decide how
composition, content, typography, imagery and motion support that experience.
Choose one creative specialist using [providers](../specialists/providers.md).

When the user supplies no references, gather a small set of relevant visual
examples with host search/browser tools, or generate concept comps/assets when
available. The agent does this work, not the user. Inspect the examples, record
what principle is useful, and avoid borrowing unrelated fragments indiscriminately.
Missing discovery tools permits a code-led prototype with disclosed assumptions.

Make the direction visible: build a small rendered screen and meaningful
interaction, or use an image comp for visual exploration followed by a clickable
slice. Consider more than one candidate when the structure is uncertain or the
user asks, using the same representative content and task. A palette-only change
does not test a different experience.

Compare the visible results for hierarchy, reading rhythm, useful density,
typographic character, imagery, accessible contrast and clarity of action.
Explain concrete tradeoffs; naming a style is not evidence of visual quality.
Let the user react when useful, or select and recommend a direction when they
prefer autonomy. Preserve that choice through subsequent refinement.

Record screenshots/prototype paths, the selected direction and why in the
fingerprint. Existing creativeDirection/exploration fields are compatible storage,
not mandatory forms. A legacy gate.status of passed does not establish current
quality. Retain old decisions as context but verify them against the current task.
