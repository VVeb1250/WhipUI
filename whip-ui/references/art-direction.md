# Art direction and identity translation

Read for new expressive surfaces, replacement brand direction, editorial/portfolio/marketing screens, or feedback that a UI looks indistinct. Skip for `MATCH`, `EXTEND`, trivial fixes, and established approved aesthetics.

## Find the visual world in THIS problem

Ask what authentic material the product contains: artifacts, domain objects, language, visuals, tools, user behavior, culture, technologies and history. Use that to find a coherent concept, not a generic style label.

```
Product truth: industrial inspection platform with actual sensor traces
Desired feeling: precise + trustworthy under pressure
Visual thesis: operational instrument panel, but legible and calm
Anchor: trace topology becomes an interactive information graphic
Hierarchy: anomalies first; metadata and explanation subordinate
Restraint: no gradients/ornaments unrelated to sensor signals
```

A concept is useful only if you can explain **why its composition, visual material, interaction and content** fit the audience's job. "Premium dark SaaS" is not enough. A different concept might be preferable for a public marketing page vs daily expert operations.

## Choose the organizing gesture

Decide what gets the strongest visual emphasis: a hero artifact, type composition, product interaction, unusual spatial arrangement, illustration, data object, or cinematic transition. An unusual grid does not by itself create identity. Spend distinctiveness where it conveys meaning; quieter supporting elements establish usability and rhythm.

Create a **visual grammar**, not a mockup fixture:

- Principle: "editorial storytelling interrupted by interactive game-state feedback."
- Good freedom: section lengths, exact coordinates, CSS mechanism, crop and typographic breakpoints.
- Explicit invariant if approved: "project cards respond to focus and hover in a game-like way, with touch equivalent."
- Bad fixture: "every card must have a 3px neon blue border, a left 40px icon, and 28px round corners" unless owner approved those details.

## Use references intelligently

Separate **art direction** from **task flow**. Learn type treatment from one reference, interaction states from another, accessibility from platform guidance. Don't multiply decorative motifs because multiple sources were cited. Refer to `whip-design/references/reference-intelligence.md` if the brief remains taste-sensitive. If the user has approved a concept, do not reopen it to impress them with a trend.

## Asset design

List visible assets with origin and constraints: existing approved brand artwork, supplied files, generated-original graphics, UI-native diagrams, or placeholder. Prefer appropriate authentic project images/screenshots over meaningless hero stock photos. Missing assets must be visible as a limitation, not hidden behind fictional achievements. Keep an asset provenance note for licensed, user-supplied or generated assets.

## Diagnose why a page looks generic

1. Replace brand words with a competing company's name. Would page still work without change? If so, the concept may not be anchored.
2. Is attention organized around a meaningful object/task or a default hero + 3-card benefit grid?
3. Is the most characteristic asset/content above the fold or buried under abstract blobs?
4. Are type, palette, image crop and motion all serving one thesis, or are they merely trendy?
5. Does removing the loudest flourish make UX clearer without hurting meaning? If yes, consider removing it.

An expressive concept isn't an excuse to compromise accessibility, product truth, performance, or user control.
