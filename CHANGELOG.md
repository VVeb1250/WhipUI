# Changelog

## 3.1.0-rc.1 (release candidate, 2026-10-14)

Combines the unreleased Combo and game-route work below under a minor release
candidate. Keeps the public package/skill names, installer options and host
locations. Adds eight pinned method libraries with bounded ownership and source
adapters, Impeccable prototype/feedback for new visual worlds, and a game workflow
for player decisions and browser input/clock boundaries.

Existing v3 intent/state JSON remains supported input, with explicit field and
authority interpretation. Retains both original examples and the optional
repository provenance guard/regressions unchanged from v3.0.0. This compatibility
support does not require JSON on new projects or restore a legacy state engine.

The 4.0.0-beta versions below were local experiments, never stable releases.
Game-route usability and the sandbox-blocked installer cases remain outstanding;
this RC does not establish improved human task success or visual superiority.

## 4.0.0-beta.2 (local candidate, 2026-10-14)

Makes Impeccable the visual lead for a new/unresolved world, followed by a viewable
prototype and owner feedback. Existing identity and precise/local changes retain
their narrow route. Taste/frontend-design are selected challengers rather than
automatic competing pipelines. Adds pinned Game UI Design and OpenAI Game UI
Frontend references, with a game workflow for player decisions, comparison,
scene/input ownership and actual first-session verification. Structural UX
findings require evidence that their decision obstacle changed. Eight retained
sources still expose only two Whip entrypoints; no game engine is installed.

Game-route outcome validation is tracked separately from source/installer checks.
No published release or claim of universal superiority accompanies this candidate.

## 4.0.0-beta.1 (local candidate, 2026-10-13)

Rebuilds Whip as a guided Combo of six pinned source libraries with explicit
decision ownership, conditional routing and conflict adapters. Retains real
UX/research/IA, calibration, craft/motion, retrieval and visual tool mechanisms.
Replaces the 3.0 generic references and separate intent JSON schema/validator
with one shared conversational core and project-native authorities. Existing
project data and prior releases remain available for rollback.

Only whip-design and whip-ui are discoverable. Retained source bodies stay
unchanged under REFERENCE.md with original licenses and file hashes. The local
installer archives recognized prior copies; no hooks/services/accounts are set up.


## 3.0.0 (2026-10-13)

Replaces 2.0.0 with two standalone skills: `whip-design` for co-design and `whip-ui`
for frontend execution. Each loads its own references as needed; shared intent and
source material stay adjacent. The npm package name remains `whipui`.

### Migration

- New invocation names: `$whip-design` / `$whip-ui`, or the equivalent Claude commands.
- `npx whipui@latest --replace` archives recognized old installations and existing
  skill files outside active discovery before installing the pair.
- Claude plugin metadata loads both skills. No Stop hook or MCP setup is included.
- Retires the old `whipui` skill, bundled render/state scripts, browser dependency
  setup, legacy installer flags and JavaScript library exports. Existing project
  content and state files are preserved; approvals are not inferred or auto-imported.

### Verification

Fixes recycled approval evidence, malformed locators, unauthorized scope changes
and pinned-constraint removal in the pack's provenance guard. Adds regression and
transactional installer coverage. Candidate status remains: these checks do not
prove design-quality gains. Historical releases and experiments remain in Git history.
